# autoresearch-manager：本批最需要的修改

优先级最高的问题是恢复语义：一次临时故障会丢弃同阶段已经成功的另一侧，重跑长研究或重新进行独立 QA。对于每侧至少 10h 的训练研究，这会直接浪费预算，并改变原本应保留的证据。它比继续扩写提示词更需要先修。

## 复现、根因与修改

| 问题 | 修复前证据 / 根因 | 修复 |
|---|---|---|
| PASS + RETRY/NEEDS_INPUT 重跑成功侧 | 原有 15 项测试全过，独立新增的 6 项恢复/配置测试全失败；`jobs={}` 清掉整组任务 | 成功侧写入 completed，保存真实 job 路径和证据哈希，仅重开临时失败侧 |
| 配置恢复重跑已结束但未收割的双轨 | plan 偶然改动触发 NEEDS_INPUT；恢复 plan 后 resume 将 job 数由 2 增到 4 | 用 input_jobs 区分明确 driver 缺输入与配置阻塞；配置恢复后收割原 jobs |
| 复用失效旧结果 | 仅保留结果会有跨版本/改写证据风险 | 派发/收割前核对 revision、合同、任务与证据哈希；变化进入 repair；等在途任务结束，避免孤立任务 |
| RETRY 掩盖同批 FAIL | 并发状态存在优先级歧义 | 任一实质 FAIL 先进入 repair，新 revision 使旧引用失效 |
| 不存在的 Python driver 通过 doctor | 只检查解释器 executable，未检查 argv 中脚本 | Python/PyPy 直接脚本必须为存在的绝对路径；doctor 明示只检配置 |
| 同模型改 version/provider 充当双 AI | 原 reviewer 判重包含 version | 标准化 model 名判重，要求两个不同模型；真实网关身份仍需运行验证 |
| 选题交接被误当全流程启动 | 任务范围未区分 | Skill 明确区分选题/交接与真实正式执行；无授权不自动启动十题长实验 |

修改文件：`SKILL.md`、`references/runtime-contract.md`、`scripts/manager.py`。新增三组可复现行为测试，共 19 项；另把旧测试中一个本地路径变量改名，避免隐私扫描器把示例路径变量误认成凭据。未修改固定 QA v0.3.4 的 34 个文件，也未降低训练时间、稳定性或双 PASS 要求。

## 验证结论

独立审查会话从临时快照复测：原有 15 + 恢复回归 10 + 额外恢复 5 + input marker 4 = **34 项全部通过**。详见 [独立报告](independent-review.md) 与本目录日志。生产 `manager.py` 的被测 SHA256：`e7dbc35e2972340b8f638d71efbfed2bfad8137ec8357ade580b63630535b611`。

主控另运行实际 Docker 隔离测试，检查两次新容器、相同 ZIP、只读 input/skills、各自空 out、无长期凭据环境，以及 driver 被终止后不会遗留活容器。模型可执行文件为明确标记的模拟程序；这不是实际模型路由或题目 QA。

## 尚未自动保证的事项

manager 不自动锁定外部 driver 文件内容，不能证明远程命令、shell、`python -m` 或网关实际可用；接手者必须记录脚本/镜像哈希并以不可变目录部署，通过真实预检。model 字符串检查也不能识别网关底层别名，真实模型身份须由网关证据核验。

框架测试不能证明十题的训练质量、收益、10h 有效研究、12h 稳定性或最终双 AI PASS。修正版随仓库交付；本机全局 skill 和已有运行状态保持原样，接手按 runbook 在安全边界使用新版本。

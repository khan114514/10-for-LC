# 十题共同制作与验收要求

## 用户目标和状态

十个题目均须包含真实训练，能够复现和完成正式题包，目标难度为中等。每题优先按一天目标推进，必要时放宽到两天；不能为满足时间目标缩减必需证据或虚报完成。

当前为选题交接：正式论文、官方源码、公开数据入口及在线查重已检查（未完整下载和验证全部数据资产），中等评级是基于指定范围的预评。未完成目标机器的端到端训练、正式 B/R、Reference 增益、Harbor、双轨迹和最终 QA。开工重新核对当期平台规则与最新查重，冻结任务后用实际成本和方差复评难度；不符合中等范围或真实改善条件就更换题目。

本交接内容采用 [V4 教程合同](../skills/autoresearch-manager/references/phase3-v4-contract.md)，不继承此前批次的豁免。随附机器执行器和固定 QA 资产仍为 v0.3.4；真实官方 0.3.10 发布包及格式/GPU/指纹脚本尚未取得，不能用旧版 PASS 声称新版完整验收。正式运行前取得真实发布包、核对并适配报告合同，记录差异并复验受影响证据，不中途静默替换版本。

## 题目合同和方法空间

先冻结数据、切分、预处理、正式 seed 全集、输入输出、可修改代码面、资源上限、checkpoint 选择、指标方向、质量门及 B/R/U。

候选须能通过函数、模块或策略接口实现方法改动，包括目标形式、采样、模型模块、训练更新或推理算法。若接口只接受学习率、损失权重、轮数等标量，不能通过 G01。具体题目文件是作者侧设计要求，转成参赛者 instruction 时不能泄露论文名称、答案仓、Reference 方向或作者路径。

公开 Dev 必须可供研究迭代。私有集不用于选择 Reference 或调阈值，数据与指标质量门不得看结果后放宽。按任务类型正确处理时间、用户、图或样本分组，防止相邻片段和重复实体泄漏。

## 健康 Baseline 与真实 Reference

正式 B 采用可运行、可解释且有代表性的完整方法；合理朴素 Starter 或 Scaffold 可以采用，但评分锚点绑定经审查的正式 B。不得去掉核心输入/模块、故障实现、无依据少训练或挑最差 seed 来制造空间。

依赖适配、公共缓存、数据预处理与指标修复两边共用，不能作为方法创新收益。训练是否充分根据实际 steps、曲线、早停和 checkpoint 判断，不能仅看配置中的 epochs。

B/R 使用同数据、切分、评测、正式 seed、资源上限及可比搜索机会。固定正式 seed 全集后完整交付；默认至少三次独立从初始化训练，高方差使用至少五次。重复评价同一 checkpoint 不能冒充独立训练。

每次正式训练保留真实 checkpoint、源码/配置标识、原始命令和日志、起止、退出码、成本及模型 SHA256。独立新进程从 checkpoint 重载并重新评分，记录实际结果。失败或更差的运行同样保留。

G03 使用全部正式原始值复算：随机评估平均改善至少 `3 × σ_B`，其中 `σ_B` 是 Baseline 样本标准差、分母为 n−1。归一化 Reference 分数在 `[0.15, 0.8]`；U 依据独立可达估计或指标上限确定，不根据 Reference 调整。保留合理余量，解释高方差及 headroom 风险。

## 正式模型组合与凭据边界

两条独立轨迹采用相同任务版本、提示与资源协议：

| 轨迹 | 模型和设置 | 路由 |
|---|---|---|
| Codex + GPT | `gpt-6.1-sol`，`xhigh` | 用户指定 ModCon：`https://modcon.top/v1`，Responses API |
| Codex + Seed | `doubao-seed-2-1-turbo-260628`，`high` | 火山 Coding Plan：`https://ark.cn-beijing.volces.com/api/coding/v3/chat/completions` |

模型、推理档位或套餐不支持时报告具体缺项，保持未完成，不自行替换或回退按量路由。网关需先实测 Codex 工具调用、模型路由、隔离和实际评分能力，普通聊天响应不构成正式 Codex 轨迹。

凭据在可信主控侧读取当前用户授权配置。配置位置由接手机器通过 `ARK_CONFIG_PATH` 等主控参数指定。长期密钥不得回显、写入通知、日志、request、plan、版本库、题包或 Actor 环境；两轨迹之间不得互相访问方法与结果。

## manager 全流程

真实预跑、合法 B/R、隔离、模型和评分器验证完成后执行：

`prepare → br → preflight_nop → dual_a/dual_b → finalize → nop → stability → package → qa_a/qa_b → consensus`

失败进入实质 repair，建立新 revision 并按合同复验，不把旧版本 PASS 与新版本证据拼接。每个 driver 采用已实测命令，保存实际退出、产物及哈希。上下文续接用磁盘状态及新会话恢复，保留在途进程和用户暂停状态。

十题都涉及训练，两条模型轨迹每条至少 **10 个有效研究小时**；7h 非训练例外不适用。安装、排队、构建失败、睡眠、阻塞和进程存活时长不能当有效研究时间。每轮记录真实方法改动、Public/Dev 评分与下一步决策。

两条轨迹的最终方法分别按当前源码 SHA 与冻结合同，在干净快照中独立复验。finalize 不改冻结作者输入；装配产物写到本阶段输出。

另验证同一实际容器在声明负载和健康检查下稳定至少 **12 小时**，无重启；管理器等待不能代替稳定性观察。

## Harbor、评分和目录隔离

冻结所选 Harbor 版本及目标构建 profile。Solver 与 Verifier 使用不同 sandbox，可复用 Solver 镜像或提供专用 Verifier 镜像，不强制双 Dockerfile；配置 `[verifier] environment_mode = "separate"`。明确 COPY、WORKDIR、入口、构建上下文和最终提交移交，实际运行验证，不能混用不兼容布局。

评分器从候选代码和真实权重重新运行并计算指标，拒绝缺失 case、旧结果、篡改资产和候选自报分数；成功结果原子写出。区分格式错误、质量门失败、资源超限与基础设施错误。

候选不可读取 Hidden、Reference、专家证据、管理配置或其他轨迹；测试结束后向独立 Verifier 移交提交，私有材料安全注入。沙箱失败必须修复，不能绕过。

当前题包必须真实完成 NOP 构建、Trial、独立 Verifier 并产出有效 reward，保留 config/result/reward/log。NOP 为零分本身不判失败。

最终按冻结平台合同交付三类职责目录：

- `workspace/`：公开任务及作者侧独立 reference；reference 保持 Actor 不可访问。
- `expert_evidence/`：best_method、专家说明、双轨迹和实际结果摘要。
- `optimization_evidence/`：全部正式成对训练、原始指标、日志、模型索引和重载证据。

详细路径、八字段轨迹、四项指纹及格式按 V4 内容合同与冻结平台版本核验；旧 QA 只用于其真实版本的辅助清点，冲突不得静默忽略。目标 GPU、联网约束、当前镜像/调用与 NOP 均须有实际验证，缺口不能套用此前批次豁免。

## 双 AI 独立质检与完成条件

两个不同 AI 在实际全新隔离审查会话/容器中，各只接收同一个完整最终 ZIP、固定 QA Skill 和空输出目录。首轮不接收作者历史、旧报告、另一审查结论或管理状态，不挂 Docker socket 或长期凭据。

报告绑定同一 ZIP SHA256、QA 版本、模型身份与真实 session/容器启动证据，使用原版 release-self-check，完成 G01–G03、QA01–QA21、H01–H06。独立报告形成后再用原版聚合器复核分歧。任一硬失败或未解决分歧即 NOT READY，不做多数投票。

失败持续修正作者产物，形成新包和新哈希后重新独立审查。只有同一最终 ZIP 的两份 PASS 且共识无分歧、真实运行和必需证据齐全，才算本地全流程完成。

发布前对题包、QA、自检、轨迹、证据和交接附件分别做严格隐私/可移植性检查。提交结果须区分本地完成和平台正式收录。
